# Contributing

Thanks for your interest in improving this project! Before diving in, please skim the `README.md` to get a sense of the project's purpose and layout. The notes below describe how to report issues and submit changes in a way that keeps reviews quick and friendly.

## Reporting Issues

- Search existing issues first to avoid filing duplicates.
- Include clear, minimal steps to reproduce the problem.
- Provide environment details (OS, runtime version, and any relevant configuration).

## Submitting Changes

- Fork the repository and create a feature branch off `main` for your work.
- Make descriptive commits as you go and open a pull request against `main` when ready.
- Prefer small, focused pull requests over large omnibus changes; they are much easier to review and land.

## Commit Messages

- Write commit subjects in the imperative mood (e.g., "Add", "Fix", "Update").
- Keep the subject line to 72 characters or fewer.
- Reference related issues using `#N` (for example, `Fix crash on startup (#42)`).

## Code Style

- Follow the existing conventions in the surrounding code; match the style you see rather than introducing new patterns.
