# Contributing

Welcome, and thank you for helping make this project better! Before you dive in,
please take a moment to read `README.md` — it covers the project's goals and how
to get your local environment up and running.

## Reporting Issues

- Check the issue tracker first; your problem may already be reported or resolved.
- Describe the bug with a minimal, reproducible example so maintainers can verify it.
- State your operating system, runtime, and any other version information that is relevant.

## Submitting Changes

- Fork this repository to your own account before making any edits.
- Branch off `main` and give your branch a short, descriptive name.
- Keep each pull request focused on a single concern to make review straightforward.
- Open your PR against `main` and fill in the description with the motivation for the change.
- Prefer a series of small commits over one large commit that mixes unrelated edits.

## Commit Messages

- Write the subject line in the imperative mood (e.g., "Add", "Fix", "Remove").
- Limit the subject line to 72 characters so log output stays readable.
- Mention related issues with `#N` notation (e.g., `Closes #7`) where appropriate.

## Code Style

- Follow the conventions already present in the codebase — consistency is the goal.
- Avoid mixing style fixes with functional changes in the same commit.
- Run all available formatters and linters before opening your pull request.
